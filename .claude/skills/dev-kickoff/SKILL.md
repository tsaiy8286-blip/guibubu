# Dev Kickoff：網站開案 SOP

這個 skill 在專案的第一天把「規則」裝進專案：協作紅線（專案 CLAUDE.md）、計劃與追蹤文件。裝好之後，這個專案的每一次對話都會自動遵守紅線——這是整套流程的地基。

**使用者背景**：使用者完全沒有程式經驗。所有專有名詞第一次出現都要用一句白話解釋；需要使用者做決定時，給選項、附你的建議與理由，不要丟開放式問題。

**互動原則**：本 skill 全程需要與使用者討論確認，不可派給背景 subagent 執行。

**模板原則**：所有文件一律從 `assets/` 的模板生成，填入占位符即可，**不可自行增刪模板內容**（尤其是紅線條文）。

**技術預設**：純 HTML／CSS／JavaScript 的靜態網站——不用框架、不用建置（build）、不用資料庫、不用安裝套件。檔案直接用瀏覽器雙擊就能打開。只有使用者的需求明確做不到時，才提案其他技術，並說明代價。

---

## 步驟零：判斷模式

看目前資料夾的狀態：

- **新專案**：空資料夾或只有零星檔案 → 走完整流程（步驟一～七）
- **既有專案**：已經有網頁檔案 → 走完整流程，但遵守「既有專案規則」（見下方），只補缺的部分

順便確認電腦上有 git（執行 `git --version`）。沒有的話，停下來引導使用者安裝（Windows：https://git-scm.com/download/win ，安裝選項全部用預設；Mac：在終端機輸入 `xcode-select --install`），裝好再繼續。

---

## 步驟一：一次問完開案問卷

用一則訊息把以下問題全部問完，不要分多輪：

1. **網站名稱**，和一句話說明：這個網站要給誰看、拿來做什麼？
2. **大概有哪些頁面或內容？**（例如：首頁、作品集、關於我、聯絡方式。想到多少寫多少，之後可以改）
3. **有沒有喜歡的網站可以參考風格？**（貼網址或描述就好，沒有也沒關係）
4. **要不要放上網路讓別人看？** 用下表說明後討論決定：

| 選項 | 適合誰 | 說明 |
|------|--------|------|
| 先不上線 | 只是自己用、還在試做 | 檔案放在自己電腦，雙擊打開就能用。之後要上線隨時可以加 |
| Netlify Drop | 想最快上線、不想碰 GitHub | 把網站資料夾拖到 https://app.netlify.com/drop 就有網址；每次改完要重新拖一次 |
| GitHub + Cloudflare Pages 或 Netlify | 會常常更新內容 | 檔案存到 GitHub（程式碼的雲端硬碟），每次存檔推上去（push），網站自動更新；要先申請 GitHub 帳號 |

使用者拿不定主意時，建議「先不上線」，等網站做出雛形再決定。

**提醒使用者一件事**：靜態網站上的所有內容都是公開的，任何人都看得到原始檔。不要把個人電話、身分證號、密碼、私人金鑰寫進網站檔案裡。

**完成判準**：四個問題都有明確答案，才進入步驟二。

---

## 步驟二：生成專案 CLAUDE.md

從 `assets/CLAUDE.template.md` 填入占位符（專案資訊、日期），寫進專案根目錄的 `CLAUDE.md`：

- `CLAUDE.md` 已存在（安裝工具包時放的基本規則）→ **接在檔案最後面**，前面的內容一字不動
- 不存在 → 直接建立

生成後用白話向使用者說明：「這份檔案是給 AI 看的規則，以後每次在這個資料夾開對話，AI 都會先讀它。」然後把六條紅線逐條用一句話解釋給使用者聽。

---

## 步驟三：建立資料夾骨架

```
（專案資料夾）
├── index.html      ← 首頁（先放一個最簡單的「施工中」頁面，確認瀏覽器打得開）
├── css/
├── js/
├── images/
└── docs/
    └── cards/      ← 之後的任務卡放這裡
```

`docs/SPEC.md`（網站規格）**不在此建立**，由第一次 `/dev-spec` 從討論中生成。

建好後請使用者雙擊 `index.html`，確認瀏覽器能打開「施工中」頁面。這是使用者第一次親眼看到成果，很重要。

---

## 步驟四：建立 .gitignore

從 `assets/gitignore` 複製為專案根目錄的 `.gitignore`。用一句話說明：「這份清單告訴 git 哪些檔案不要存，例如放密碼的 `.env` 和系統自動產生的雜檔。」

---

## 步驟五：生成計劃與追蹤文件

從 assets 生成兩份文件到專案根目錄：

- `assets/project-plan.template.md` → `專案計劃.md`
- `assets/project-tracker.template.md` → `專案進度追蹤.md`

---

## 步驟六：討論並填寫專案計劃

這一步是**對話，不是模板填空**。用步驟一的回答當起點，跟使用者逐節討論 `專案計劃.md`：

1. 網站目標（給誰看、看完希望他們做什麼）
2. 第一版要有的頁面與內容（提醒：先做最少、能看的版本，其他想法放第四節）
3. 網站風格（顏色、感覺、參考網站）
4. 「這次不做的事」（防止越做越大）
5. 里程碑：第一版長什麼樣子算完成

---

## 步驟七：第一次存檔

呼叫 `git-commit` skill 完成第一次 commit（它會處理 git init、安全掃描、commit 說明）。不要直接下 git 指令。

用一句話跟使用者說明 commit 是什麼：「commit 就像遊戲存檔，之後改壞了可以回到這個點。」

---

## 既有專案規則

既有網站資料夾要補規則時，額外遵守：

1. **先盤點再動手**：列出「已有什麼、缺什麼」的清單給使用者看，經同意後只補缺的
2. **不覆蓋既有檔案**：已有 .gitignore，或 CLAUDE.md 裡已經有紅線段落時，列出模板中它缺少的條目，經使用者同意後逐條加入，不整檔覆蓋
3. **不動既有網頁**：本 skill 只裝規則，不改網站內容
4. 跳過步驟三的「施工中」首頁；既有網站還沒有 SPEC.md，提醒使用者之後可以跑一次 `/dev-spec` 把現有網站整理成規格

---

## 完成檢核（結束前逐項回報 ✅/❌/不適用）

- [ ] git 已安裝
- [ ] 專案 CLAUDE.md 已生成，紅線已用白話解釋給使用者
- [ ] 資料夾骨架已建立，使用者親眼打開過 `index.html`
- [ ] .gitignore 已建立
- [ ] `專案計劃.md` 已與使用者討論填寫完成
- [ ] `專案進度追蹤.md` 已建立
- [ ] 第一次 commit 完成（走 git-commit skill）

全部回報後，告訴使用者接下來怎麼做：

> 「開案完成！接下來說『我要做 XX』或打 `/dev-spec`，我們會先把第一版網站要長什麼樣子講清楚，再拆成一張一張的小任務慢慢做。」
